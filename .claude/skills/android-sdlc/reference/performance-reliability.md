# Performance, reliability & observability reference

Measure on the reference **low-end** device and a throttled network, with a release-like build. The budgets come from the NFRs.

## Performance
### Startup
- **Lean `Application.onCreate`.** Initialise SDKs lazily, or with App Startup. No disk or network I/O on the main thread at launch.
- **Baseline Profiles.** Ship a Baseline Profile and a Startup Profile, generated by a Macrobenchmark module. Regenerate them every release.
- **Local data first.** Show content from the local database, then refresh in the background.
- **Splash.** Use the SplashScreen API, with no artificial delay.

### Rendering (Compose)
- **Read state as late as possible.** Pass lambdas (`{ offset }`) for fast-changing values, and use `derivedStateOf` for values derived from them.
- **Lists.** Use stable, immutable UI models. Lazy lists get a `key` (`items(notes, key = Note::id)`), plus a `contentType` when items are mixed.
- **No allocation or sorting during composition.** Do that work in the ViewModel.
- **When a screen janks,** check the Compose compiler reports and the recomposition counts in Layout Inspector.

### Main thread, memory and network
- **StrictMode** in debug catches disk and network access on the main thread.
- **LeakCanary** in debug. Never hold an Activity, View or Context in a singleton or ViewModel; use `@ApplicationContext`.
- **Images:** Coil loads them at the displayed size, with memory and disk caches.
- **Lists and network:**
  - Paging 3 for long lists.
  - An OkHttp disk cache that honours `Cache-Control`.
  - Work that belongs to a screen runs in `viewModelScope`, so it's cancelled with the screen.

### Size and battery
- **App size.**
  - R8 full mode, resource shrinking and AAB delivery.
  - Vector drawables and WebP images.
  - Review the APK Analyzer before each release.
- **Background work** runs only through WorkManager, with constraints (network, charging, battery not low).
  - Never poll; use FCM for push.
- **Location.** Ask for coarse location unless precise is required, and stop updates when nothing on screen needs them.

## Reliability
- **Offline-first,** where the requirements need it. Room is the single source of truth: the UI observes it, and the network refreshes it.
- **Offline writes.**
  - Save locally and mark the change as pending.
  - Sync it with a unique WorkManager job.
  - Send an **idempotency key**, so a retry can't create a duplicate.
- **Retries.**
  - Exponential backoff with jitter.
  - Honour HTTP 429/503 and `Retry-After`.
  - Never blindly retry a call that isn't idempotent.
- **Conflicts** follow the policy from the architecture document, e.g. last write wins on server timestamps, or the user resolves them.
- **Tolerant parsing.**
  - `Json { ignoreUnknownKeys = true }`.
  - Defaults for optional fields.
  - An `UNKNOWN` value for enums.
- **Room migrations.**
  - `exportSchema = true`, with the schemas committed.
  - A `MigrationTestHelper` test for every version.
  - Never `fallbackToDestructiveMigration` in production.
- **Process death and configuration changes.**
  - UI state lives in ViewModels.
  - Inputs that must be restored go in `SavedStateHandle` or `rememberSaveable`.
  - Navigation arguments live in routes.
  - Test with "Don't keep activities".
- **Safety nets:**
  - a remote-config kill switch for each risky feature;
  - a minimum-version check, with In-App Updates for forced updates.

## Scalability (client side)
- **Modularise** along the [module layout](architecture.md#module-layout), so features and teams scale independently.
- **Keep builds fast:** build cache, configuration cache, no needless `api` dependencies.
- **Protect the backend.**
  - Delta sync with server tokens.
  - Coalesce identical requests.
  - Paginate everywhere.
  - Add jitter to scheduled syncs, so devices don't all hit the server at once.
- **Feature flags** separate deploying from releasing, and let you shed load in an incident.

## Observability
- **Crash and ANR reporting,** with CI uploading the R8 mapping file for every release.
- **Android vitals** in Play Console: crash rate, ANR rate, startup, slow and frozen frames, excessive wake-ups. Break them down by version and device.
- **Performance monitoring:** custom traces for key journeys (e.g. "open note"), plus network latency and error rates.
- **Analytics.**
  - Events come from the tracking plan, with `snake_case` names and documented parameters.
  - Analytics is gated by consent and carries no PII.
- **Logs.** Timber with a debug tree. In release, only breadcrumbs without PII go to the crash reporter.
- **Correlation IDs.** An OkHttp interceptor adds a request-ID header, so a user's call can be traced in the backend.
- **Release dashboard:** crash-free users, ANR rate and adoption for each version. It drives the staged-rollout decisions.
